# Oh-My-OpenLog —— 高性能 C++ 日志库

oh-my-openlog 是一个基于 C++11 开发的高性能日志库（线程安全），支持同步和异步日志输出。它采用了建造者模式进行日志器的构建，支持多种日志落地方向（Sinks），并提供了灵活的日志格式化功能。不依赖任何第三方库，Linux 下直接就能跑。

## 1. 核心特性

- **高性能**：异步模式下支持海量日志写入，在 **4 核 4GB** 云服务器上，单机 **每秒处理能力** 可达 **93.78 万条/秒**。
- **多种落地方式**：
  - 标准输出（`StdoutSink`）
  - 普通文件（`FileSink`）
  - 按文件大小滚动的日志文件（`RollBySizeSink`）
  - 【扩展】按时间段滚动的日志文件（`RollByTimeSink`，见 examples）
- **灵活的模式**：支持 **同步（Sync）** 和 **异步（Async）** 两种日志输出模式。
- **异步安全机制**：异步模式提供“安全”与“非安全”两种选择（安全模式支持 **满载阻塞保护**，防止内存爆满）。
- **多级日志**：DEBUG、INFO、WARN、ERROR、FATAL、OFF，按需过滤。
- **自定义格式**：`%d`（时间）、`%t`（线程 ID）、`%p`（级别）、`%f`（文件名）等占位符，顺序随便排。
- **便捷接口**：提供全局单例管理器和简单的宏函数（如 `INFO()`, `DEBUG()`），实现零配置快速上手。
- **线程安全**：所有操作均经过锁保护，支持多线程并发写入。

## 2. 项目结构

-   **LogMsg**：装单条日志的所有字段（时间、线程、级别、文件、行号、内容）。
-   **Formatter**：解析格式字符串，按顺序把字段拼成最终文本。支持扩展新占位符。
-   **LogSink**：负责真把日志写出去。纯虚基类，派生出 `StdoutSink`、`FileSink`、`RollSink`。加新落地方向不动老代码。
-   **Logger**：对外暴露 `debug()`、`info()` 等。分同步和异步两个子类。
-   **AsyncLooper**：异步核心、双缓冲队列。业务线程只管塞，后台线程批量取、批量写。锁冲突少，内存不碎片。
-   **LoggerManager**：单例、管所有日志器。全局任意位置都能按名字拿到对应的日志器。

## 3. 快速开始

### 1. 引入头文件

只需包含 `source/mylog.h` 即可使用所有功能：

```cpp
#include "source/mylog.h"
```

### 2. 使用默认日志器（宏接口）

```cpp
#include "source/mylog.h"

int main()
{
    // 使用默认的 root 日志器输出日志
    DEBUG("这条是调试信息: %d", 123);
    INFO("系统运行正常");
    ERROR("发生错误: %s", "连接超时");
    return 0;
}
```

### 3. 自定义日志器（建造者模式）

#### 1. 建造者参数说明

| 方法                        | 说明                                   | 必选/可选 | 默认值                                    |
| --------------------------- | -------------------------------------- | :-------: | ----------------------------------------- |
| `buildLoggerName(name)`     | 设置 **日志器唯一名称**                   | **必选**  | 无                                        |
| `buildLoggerType(type)`     | 设置同步（Sync）或异步（Async）        |   可选    | `LOGGER_ASYNC`                            |
| `buildLoggerLevel(level)`   | 设置日志最低输出 **级别**               |   可选    | `LogLevel::value::DEBUG`           |
| `buildFormatter(pattern)`   | 设置日志 **输出格式** 模板               |   可选    | `[%d{%H:%M:%S}][%t][%c][%f:%l][%p]%T%m%n` |
| `buildSink<SinkType>(args)` | 设置 **日志落地方式**（支持同时设置多个） |   可选    | 若为空则默认为标准输出 `StdoutSink`          |
| `buildEnableUnSafeAsync()`  | 开启非安全异步（不阻塞，无限扩容）     |   可选    | 默认为安全模式（满载自动阻塞，防止内存耗尽） |

#### 2. 使用示例

使用 `GlobalLoggerBuilder` 或 `LocalLoggerBuilder` 来定制日志器。

```cpp
#include "source/mylog.h"

void test_custom_logger()
{
    // 1. 实例化建造者
    mylog::GlobalLoggerBuilder builder;
    
    // 2. 配置日志器
    builder.buildLoggerName("MyLogger");                      // [必选] 设置日志器唯一名称
    builder.buildLoggerType(mylog::LoggerType::LOGGER_ASYNC); // [可选] 默认: LOGGER_ASYNC (异步)
    builder.buildLoggerLevel(mylog::LogLevel::value::INFO);   // [可选] 默认: DEBUG (最低级别)
    builder.buildFormatter("[%d{%H:%M:%S}][%p]%m%n");         // [可选] 默认: "[%d{%H:%M:%S}][%t] [%c][%f:%l] [%p]%T%m%n"
    
    // 3. 添加输出方向 [可选]
    // 若不添加，则默认添加 StdoutSink (标准输出到屏幕)
    builder.buildSink<mylog::StdoutSink>();
    builder.buildSink<mylog::FileSink>("./logs/test.log");
    builder.buildSink<mylog::RollBySizeSink>("./logs/roll", 10 * 1024 * 1024); // 10MB 滚动
    
    // 4. [可选] 设置不安全模式，空间不足会一直扩容，可能导致内存爆满，一般不需要开启
    // builder.buildEnableUnSafeAsync();                      // 默认: ASYNC_SAFE (满载自动阻塞保护)
    
    // 5. 构建/注册好日志对象
    builder.build();

    // 6. 获取并使用
    auto logger = mylog::getLogger("MyLogger");
    logger->info("自定义日志器启动成功");
}
```

### 3. 结果分析

#### 1. 为什么多线程同步相比单线程同步反而变慢？

多线程同步在单线程同步的逻辑中增加了（或者说多了）锁机制，这个过程中需要不断的加锁和解锁，会产生性能损耗，测试结果的差异便来自于此，所以多线程同步相比单线程同步性能不增反降。（6 个线程争抢同一把锁来写入同一个文件，产生了严重的 **锁竞争**，且文件 I/O 本质上是串行的，多线程并不能加速磁盘写入）

#### 2. 为什么单线程异步会慢于同步？

在单线程环境下，异步模式并没有真正的“并行”发生。相比同步模式直接写入文件，异步模式增加了 **双缓冲区交换、条件变量通知、以及线程间同步** 的额外开销。在没有多核并行优势的情况下，这些管理开销反而拖慢了整体速度。

#### 3. 为什么单线程异步（非安全）比单线程异步（安全）要慢，但是在多线程中却呈相反状态？

- **单线程下**：非安全模式（UNSAFE）涉及动态内存扩容和更频繁的内存管理开销（频繁的堆内存申请），在没有高并发压力时，这些灵活性反而成了额外的计算负担。
- **多线程下**：非安全模式允许生产者 **永不阻塞**。即使后台落地线程处理较慢，前端 6 个生产者也可以毫无阻碍地继续高速写入缓冲区（直到内存耗尽）。而安全模式（SAFE）在缓冲区满时会触发 **满载阻塞保护**，强制生产者等待，从而限制了处理速度。

#### 4. 为什么多线程异步（非安全）是极致性能？

这是因为该模式实现了真正的 **读写分离与批量处理**：
1. **并行**：多个生产者线程在各自的 CPU 核心上并行进行日志格式化并写入各自的缓冲区，最大化了 CPU 利用率。
2. **零阻塞生产**：非安全模式下生产者永远不会因为等待缓冲区空间而阻塞，消除了 **满载阻塞保护** 带来的延迟，充分压榨 CPU 格式化能力。
3. **磁盘批量 I/O**：后台线程将成千上万条日志一次性刷入磁盘，极大地减少了系统调用（`write`）的次数，同时也有 **随机写转化为顺序写**，最大化磁盘利用率。

### 4. 小结

| 场景 | 推荐模式 | 原因 |
|------|----------|------|
| **低并发** | 单线程同步 | 简单高效，无额外开销 |
| **高并发+安全** | 多线程异步安全 | 性能优秀，有满载阻塞保护 |
| **高并发+极致性能** | 多线程异步非安全 | 性能最佳，但需注意内存占用 |
| **不建议** | 多线程同步 | 锁瓶颈严重，无任何优势 |

## 5. 核心设计

1. **双缓冲区异步写入**：生产者将日志写入前端缓冲区，后端线程负责将后端缓冲区的数据批量写入磁盘，极大地减少了系统调用的频率。
2. **解耦的 Sink 插件系统**：利用多态实现了高度可扩展的落地逻辑，支持 Stdout、File、Rolling 等多种策略，符合 **开闭原则**。
3. **精巧的建造者模式**：通过 `LoggerBuilder` 实现了复杂的日志器配置，对用户屏蔽了内部组件（Formatter，Sinks，Looper）的拼装细节。
